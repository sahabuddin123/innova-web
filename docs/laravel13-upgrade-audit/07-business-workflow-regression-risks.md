# 07. Business-Critical Workflow Regression Risks

**Project:** `innova-web` (INNOVA Computers BD / ICBD)  
**Audit Target:** Core Business Logic Integrity Preservation  
**Audit Date:** October 2026  
**Status:** Read-Only Audit (Phase 0)  
**Auditor:** Senior Laravel Fullstack Architect & QA Specialist  

---

## 1. Executive Summary

This report traces the critical business workflows implemented across `app/Http/Controllers/` and `app/Models/`. The application functions as an **Educational Management System (EMS)** and **Financial Ledger** for INNOVA Computers BD.

The audit identifies **eight high-risk architectural failure points** in the business logic:
- A race condition in Student ID (SID) generation.
- A critical payment replay vulnerability in the bKash payment callback.
- Fragile `env()` dependencies that disable SMS and payments upon running `config:cache`.
- Non-idempotent HTTP GET requests executing state changes and SMS dispatches.
- Type errors in student fee balance calculations under modern PHP.
- Incomplete database transactions leaving orphaned financial records upon failure.

## 2. Deep Workflow Traces and Failure Analysis

### 2.1 Workflow 1: Student Admission and Student ID (SID) Generation
- **Primary Controller:** [`app/Http/Controllers/Admin/StudentsController.php:214-297`](file:///c:/wamp64/www/innova-web/app/Http/Controllers/Admin/StudentsController.php#L214)
- **Primary Model:** [`app/Models/Students.php`](file:///c:/wamp64/www/innova-web/app/Models/Students.php)
- **Repository:** [`app/Repositories/StudentsRepository.php`](file:///c:/wamp64/www/innova-web/app/Repositories/StudentsRepository.php)

#### Observed Code Trace:
```php
// In StudentsController@store:
$sid = Students::orderBy('id', 'desc')->first();
$sid = $sid->id + 1; // <-- RACE CONDITION & NULL POINTER

$params = $request->except('_token');
$students = $this->studentsRepository->createStudents($params);

// SMS formatting:
$msg = "Congratulations! $name, you have admitted ... Your SID. $sid, Batch No. $batchno ...";
$smsCon = new SMSController;
$smsCon->send_sms($phone, $msg);
```

#### Identified Vulnerabilities & Regression Risks:
1. **Concurrency Race Condition:** If two staff members admit students simultaneously, both read the identical `orderBy('id', 'desc')->first()`. Both compute the same `$sid`, and the SMS sent to both students will contain the same duplicate student ID.
2. **Crash on Fresh Database:** If the `students` table is empty (e.g. after fresh installation), `$sid` is `null`. Line 233 throws a fatal error: `Attempt to read property "id" on null`.
3. **Sequence Mismatch:** Under PostgreSQL, primary keys are generated by identity sequences. Computing `$sid` prior to model insertion does not guarantee that PostgreSQL assigns that specific integer ID.
4. **No Database Transaction:** If student insertion succeeds but the SMS gateway fails or throws an exception, no transaction rollback occurs.
- **Recommended Remediation:**
  ```php
  DB::transaction(function () use ($request, $params, $phone) {
      $student = $this->studentsRepository->createStudents($params);
      $actualId = $student->id; // Use guaranteed DB sequence ID
      
      $msg = "Congratulations! {$student->sname}, your SID is {$actualId}...";
      app(SmsService::class)->send($phone, $msg);
  });
  ```
- **Severity:** High | **Verification:** Confirmed.

### 2.2 Workflow 2: Fee Collections and Student Account Balance
- **Primary Controller:** [`app/Http/Controllers/Admin/FeesTransectionsController.php:69-103`](file:///c:/wamp64/www/innova-web/app/Http/Controllers/Admin/FeesTransectionsController.php#L69)
- **Primary Model:** [`app/Models/FeesTransections.php`](file:///c:/wamp64/www/innova-web/app/Models/FeesTransections.php)

#### Observed Code Trace:
```php
// In FeesTransectionsController@store:
$fees = $this->feesRepository->createFeesTransactions($params);
$students = Students::where('id', $request->student_id)->first();
$paid = number_format($request->paidamount, 2);
$pay = FeesTransections::where('student_id', $request->student_id)->where('paymentType', 1)->sum('paidamount');
$due = $students['balance'] - $pay; // <-- STRING ARITHMETIC FATAL ERROR
$finalDue = number_format($due, 2);
```

#### Identified Vulnerabilities & Regression Risks:
1. **String Arithmetic Crash in Modern PHP:** `$students['balance']` is a string (e.g., `'15,000'`). In PHP 8.1+, arithmetic on formatted numeric strings containing commas triggers a `TypeError` or `A non-numeric value encountered` warning, completely halting payment generation.
2. **Missing Database-Level Unique Constraint:** The `fees_transections` table lacks a unique constraint on `(trxID)`. If a transaction ID is submitted twice, duplicate payment records are created.
3. **Implicit Data Truncation:** In MySQL, `sum('paidamount')` on varchar fields containing commas silently truncates at the comma (`'12,000'` sums as `12`).
- **Recommended Remediation:**
  - Standardize `students.balance` and `fees_transections.paidamount` to PostgreSQL `NUMERIC(12, 2)`.
  - Use BCMath or native float casting for balance computations:
    ```php
    $due = (float) $student->balance - (float) $pay;
    ```
- **Severity:** Critical | **Verification:** Confirmed.

### 2.3 Workflow 3: bKash Payment Gateway Integration
- **Primary Controller:** [`app/Http/Controllers/BkashController.php`](file:///c:/wamp64/www/innova-web/app/Http/Controllers/BkashController.php)
- **Routes:** [`routes/web.php:98-107`](file:///c:/wamp64/www/innova-web/routes/web.php#L98-L107)

#### Observed Code Trace:
```php
// In BkashController@authHeaders:
public function authHeaders() {
    return array(
        'Content-Type:application/json',
        'Authorization:' . Session::get('bkash_token'),
        'X-APP-Key:' . env('BKASH_CHECKOUT_APP_KEY') // <-- DIRECT ENV CALL
    );
}

// In BkashController@success:
public function success(Request $request) {
    $arr = Session::get('arr');
    $fees = new FeesTransections;
    $fees->student_id = Session::get('student_id');
    $fees->paidamount = $arr['amount'];
    $fees->paymentType = Session::get('payment_type');
    $fees->paiddate = Carbon::now()->format('Y-m-d');
    $fees->paidremark = "Pay by Bkash";
    $fees->channel = 2; // bKash channel
    $fees->status = 1;
    $fees->trxID = $arr['trxID'];
    $fees->paymentID = $arr['paymentID'];
    $fees->save(); // <-- DUPLICATE INSERTION ON REFRESH
    return view('users.profile.success');
}
```

#### Identified Vulnerabilities & Regression Risks:
1. **Payment Replay / Refresh Duplicate Insertion (CRITICAL):**
   `Route::get('/user/success')` is an idempotent HTTP `GET` endpoint. If an admitted student completes payment and refreshes the confirmation page, or if a browser prefetching engine fetches the URL, **an additional identical fee payment record is created in the database**.
2. **Missing `trxID` Uniqueness Check:** `success()` never checks if `FeesTransections::where('trxID', $arr['trxID'])->exists()`.
3. **Fragile `env()` Calls Crash on `config:cache`:** Calling `env('BKASH_CHECKOUT_APP_KEY')` directly in controller methods means that running `php artisan config:cache` in production immediately causes `env()` to return `null`, completely breaking online bKash payments!
- **Recommended Remediation:**
  1. Move all bKash credentials to `config/services.php` and access strictly via `config('services.bkash.app_key')`.
  2. Implement an idempotency check in `success()`:
     ```php
     if (FeesTransections::where('trxID', $arr['trxID'])->exists()) {
         return view('users.profile.success')->with('message', 'Payment already processed.');
     }
     ```
- **Severity:** Critical | **Verification:** Confirmed.

### 2.4 Workflow 4: SMS Gateway Integration (Elitbuzz)
- **Primary Controller:** [`app/Http/Controllers/Admin/SMSController.php`](file:///c:/wamp64/www/innova-web/app/Http/Controllers/Admin/SMSController.php)
- **Routes:** [`routes/admin.php:178, 196-200`](file:///c:/wamp64/www/innova-web/routes/admin.php#L196)

#### Observed Code Trace:
```php
// In SMSController@send_sms:
public function send_sms($phone, $msg) {
    $url = env('SMS_URL');
    $data = [
        "api_key" => env('SMS_API_KEY'),
        "type" => "text",
        "contacts" => "88" . $phone,
        "senderid" => env('SMS_SENDER_ID'),
        "msg" => $msg
    ];
    $ch = curl_init();
    curl_setopt($ch, CURLOPT_URL, $url);
    curl_setopt($ch, CURLOPT_POST, 1);
    curl_setopt($ch, CURLOPT_POSTFIELDS, $data);
    curl_setopt($ch, CURLOPT_RETURNTRANSFER, true);
    curl_setopt($ch, CURLOPT_SSL_VERIFYPEER, false); // <-- INSECURE SSL
    $response = curl_exec($ch);
    curl_close($ch);
    return $response;
}
```

#### Identified Vulnerabilities & Regression Risks:
1. **HTTP GET Mutations for Outgoing SMS:**
   ```php
   Route::get('/{id}/todaypostpond', 'Admin\SMSController@todayPostpond')->name('admin.students.sms-todaypostpond');
   Route::get('/{id}/duesms', 'Admin\SMSController@dueSMS')->name('admin.students.sms-due');
   ```
   All SMS dispatch triggers are mapped to HTTP `GET` routes. A search crawler, an accidental click, or an image tag injection (`<img src="/admin/students/10/todaypostpond">`) will automatically drain SMS credits and dispatch unintended messages to students.
2. **Disabled SSL Peer Verification (`CURLOPT_SSL_VERIFYPEER = false`):** Exposes outgoing SMS credentials and student numbers to Man-In-The-Middle interception.
3. **`env()` Caching Fragility:** Direct `env('SMS_API_KEY')` calls return `null` when `config:cache` is executed.
- **Severity:** High | **Verification:** Confirmed.

### 2.5 Workflow 5: Financial Accounting, Incomes, Expenses & Reports

## 3. Required Regression Test Suite (Parity Preservation)

| Test Suite | Target Workflow | Key Assertions to Verify |
|---|---|---|
| `StudentAdmissionTest` | Admission & SID generation | • Verify SID sequence matches DB `id`<br/>• Verify SMS queued with correct SID<br/>• Verify concurrent submissions do not conflict |
